Warping Playground: my 2022 multiplayer game, restored and upgraded with an AI coding agent

My final-year project at UTAR (2022): an online multiplayer arena game for 2–4 players in the browser, built in Unity with Photon PUN 2. The final project was not recovered, so this page shows it through my report's screenshots. The source I kept is an earlier prototype, so in October 2026 I directed Claude Code to make that prototype playable again with the smallest fixes, then upgrade it to Unity 6.3 LTS.

The game, from my 2022 report

Each player is an armoured 3D character with their own camera. A match lasts 180 seconds. Players fight each other and yellow glowing enemies, which spawn every 3–10 seconds and fire purple bullets. The weapon is a blade you can swing, throw into a wall or the floor, warp to, or use as one end of a laser. Defeating an opponent scores +20, an enemy +5, and being defeated costs 10; a ranking board closes the match.

How to play

  1. Open a version in two browser tabs (or send the link to a friend).
  2. Tab 1: Create Room, type a name, create. Tab 2: Find Room, click the room to join.
  3. The host presses Start; each player spawns as the 3D character.
  4. Move: W forward, A/D turn, S turn around, Space jump (again in the air to double-jump).
  5. Upgraded prototype: move the mouse to turn. Click to keep the pointer in the game; Esc releases it.

How the upgrade was done

The method

  • The untouched original is tag v2022-original, backed up before any upgrade work.
  • Restore with no new features: branch restore-2022-playable.
  • The upgrade: branch ai-upgrade-2026-10, which starts from the restore's first fix, in small labelled commits.
  • Each claim checked against a build, log, test or two-client play test; claims the check contradicted were rewritten or dropped.

See every change: compare the original with the upgrade.

Bugs found and fixed

  • The spawned 3D character had no movement script or follow camera; both sat on a test prefab.
  • A copy of the character placed in the level carried its own camera, drawn over the game camera, so everyone saw one fixed view.
  • The room list redrew only Photon's changes, so rooms could vanish.
  • A loading panel's saved state disagreed with the scene, so it never closed.
  • Movement added in code took the script's defaults, so jumps floated; the prototype's own tuning is copied over.

Who did what

  • Me: built the game in 2022; set the brief and the rules; caught that the agent's first fix made a test capsule the player instead of the 3D character, and had it read my report and redo the work (it also removed shooting it had added to the upgrade, which the design doesn't have); raised the security-alert question that moved the restore to the patched editor; installed the editors and approved the versions.
  • Claude Code: found the bugs in code, scene and prefab files; wrote the fixes, unit tests, build and setup scripts; connected to the live Unity editor through MCP for Unity; ran the builds and the two-client play tests.
