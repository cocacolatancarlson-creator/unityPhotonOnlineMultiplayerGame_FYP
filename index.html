How to play

  1. Open the game in two browser windows (or send the link to a friend); a room takes 2–4 players.
  2. Window 1: Create Room, type a name, create. Window 2: Find Room, click the room to join.
  3. The host presses Start Room; a 180-second match begins.
  4. W forward, Space jump, S turn around; move the mouse to turn the character and its camera.
  5. Left click: melee. Right click: throw the blade; right click again calls it back. V: warp to the stuck blade. B: laser between you and the blade.

Controls as described in my 2022 report. Two-player play of the recovered build has not been re-tested yet.

The details

The game, from my 2022 reportWhat the game is and how it plays, with 8 screenshots from my report.

Each player is an armoured 3D character with their own camera. A match lasts 180 seconds. Players fight each other and yellow glowing enemies, which spawn every 3–10 seconds and fire purple bullets. The weapon is a blade you can swing, throw into a wall or the floor, warp to, or use as one end of a laser. Defeating an opponent scores +20, an enemy +5, and being defeated costs 10; a ranking board closes the match.

How the final build was recoveredThe download, a first try that failed, the one-byte fix, the checks, and who did what.

What was wrong, and the fix

  • In August 2022 I published the build on Unity Play (the link is in my report). It does not play there today (tried October 2026), and the project's source was not recovered.
  • Claude Code downloaded my build files (31 MB, built 15 Aug 2022) and ran them locally: they worked over plain http.
  • Likely cause: the build is set to connect to Photon over plain ws://, the setting my report gives for localhost; browsers block ws:// on https pages such as Unity Play. My report says to switch the protocol before publishing there.
  • Redirecting the connection to wss:// in the page failed: the name server could not parse the game's request and disconnected it, most likely because the game still encrypted it as it would on plain ws.
  • Fix: one byte in the build's Photon settings, protocol 4 (WebSocket) → 5 (WebSocketSecure), which gives the same secure connection as my report's publishing setting. Every other object is unchanged; the asset bundle was re-compressed. No source code was needed.

Checks

  • The game now connects to Photon's servers over wss://.
  • Single-player test in a browser: menu, room, start, and about 35 seconds of a match, with enemies spawning, the HP bar dropping and the timer counting down. Two-player play not yet re-tested.
  • The original download and an unpatched copy are kept with SHA-256 hashes; the patch tool is on GitHub.

Who did what

  • Me: built the game in 2022; found that the Unity Play copy does not play; asked for the build to be recovered; chose to show the final game.
  • Claude Code: downloaded and unpacked the build, traced the failure to the connection protocol, wrote the patch tool and tested the result in a browser.

The source code I kept is an earlier prototype of the game. Claude Code also restored it and upgraded it to Unity 6.3 LTS; the changes are on GitHub: compare the original with the upgrade.
